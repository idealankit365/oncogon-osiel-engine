# Interactive 3D compound viewer

OSIEL links each completed, warning or failed experiment record to the registered molecular identity of every tested compound. The **Experiments → 3D structure** tab lets a student select a result candidate, drag to rotate it, wheel/pinch or use buttons to zoom, move the camera, spin/reset the structure, hide hydrogens, change representation and switch colour schemes.

## Actual computation path

The visualization is not a decorative drawing:

1. `GET /v1/compounds/{compound_id}/conformer-3d` resolves the registered canonical SMILES.
2. Python/RDKit adds explicit hydrogens and embeds one conformer with deterministic ETKDGv3 seed `20260822`.
3. MMFF94 optimizes the geometry when parameters are available; UFF is the declared fallback.
4. The V2000 mol block is saved to the immutable content-addressed store and returned with SHA-256, method, convergence, energy, atom counts and RDKit version.
5. 3Dmol.js 2.5.5 renders the coordinates in the browser.

The hosted demonstration includes eight conformers generated by the same Python service in `public/demo-conformers.json`. The browser first tries the live Python API and uses the checksum-labelled bundle only when that API is not configured. It never invents a replacement structure.

## Viewer controls

- Representations: ball-and-stick, stick and space filling.
- Colour schemes: element/CPK, cyan carbon, purple carbon and orange carbon.
- Camera: drag rotation, wheel/pinch zoom, zoom in/out, rotate left/right, spin and reset.
- Inspection: atom element/index on hover, canonical SMILES, coordinate method, optimization state, force-field energy, seed, atom counts and SHA-256.

Colours are visual encodings only. They do not change molecular identity, the experiment or its result.

## Reproduce the bundle and verify immutable output

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/generate_demo_conformers.py
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/e2e_conformer.py \
  --output deliverables/OSIEL_3D_Conformer_E2E_Report.json
```

## Scientific boundary

ETKDG plus a force field produces one plausible computational conformer. It is not an experimental crystal structure, a solution-state conformational ensemble, a protein-bound pose, a docking result or evidence of activity. Experimental structures should be displayed as separately versioned evidence with their source identifiers and must never be silently replaced by a generated conformer.

Official renderer documentation: [3Dmol.js tutorial](https://3dmol.csb.pitt.edu/doc/tutorial-code.html) and [GLViewer API](https://3dmol.csb.pitt.edu/doc/GLViewer.html).
