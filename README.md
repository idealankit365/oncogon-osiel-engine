# Oncogon AI OSIEL Research Engine

Developer reference implementation for the Oncogon Scientific Intelligence & Experimental Learning Engine (OSIEL). It connects a Next.js research cockpit to a Python/FastAPI cheminformatics service and demonstrates the governed loop from compound identity through prioritisation, computational experiment, QC, scientific review, and model-governance boundaries.

## One-command Docker startup

Run `./start-osiel.sh` on macOS/Linux/WSL2, or `.\start-osiel.ps1` in Windows
PowerShell. Add `--with-ai` to start Ollama and download the configured Qwen
models. See [`docs/ONE_CLICK_SETUP.md`](docs/ONE_CLICK_SETUP.md) and the complete
[`docs/INDEX.md`](docs/INDEX.md).

> Research software only. The default cockpit scorer and dose-response run are deterministic demonstrations. The optional model laboratory trains a real endpoint-specific baseline from a bounded ChEMBL snapshot, but it is not independently validated efficacy evidence. Simulated results remain prohibited from training, and no model can promote itself.

## Included

- Next.js workbench with task context, evidence, ADMET, transparent seven-component ranking, candidate comparison, experiment planning, and governance views.
- FastAPI backend with typed schemas, OpenAPI, RDKit standardisation and descriptors, SQLite reference persistence, audit events, and governed live/bulk scientific connectors.
- 192 RDKit-validated development structures; presence in the registry does not establish oncology activity.
- Deterministic prediction hypotheses with intervals, uncertainty, applicability-domain status, nearest-analogue context, and rule-labelled ADMET endpoints.
- Computational CellTiter-Glo dry-run with dose series, replicates, controls, 72 synthetic observations, QC, review, immutable-snapshot gate, and champion/challenger boundary.
- Functional workspaces for registry, literature/evidence, prediction, ranking policies, scientific copilot, experiments, model governance, audit/lineage, and safety settings.
- Searchable A549-focused literature registry with 12 PubMed-linked study records; only metadata and concise study-context summaries are stored.
- Visible 96-well plate map, dose-response equation and curves, raw-like observation preview, automated QC results, and rejected training-eligibility decision.
- Production-readiness control center with phase gates, external-dependency ledger, runtime truth, and role-permission simulation.
- Server-enforced production API-key/role boundary, immutable content-addressed raw-file storage, and a qualified-adapter contract for plate-reader imports.
- A developer-grade SRS and a machine-readable end-to-end execution report.
- Public-source Open Discovery workspace with optional Open Targets, PubChem, ChEMBL, RCSB PDB and AlphaFold DB clients; local RDKit similarity/QED/Lipinski/PAINS-Brenk-NIH computation; a live bounded SmallWorld query of a provider-reported 10.10B-entry map; and real operator-gated AutoDock Vina execution.
- Ten-stage scientist-visible operational trace showing executed, deferred, failed and human-controlled steps without exposing hidden model reasoning.
- Governed local Professor AI: immutable PDF/TXT/Markdown ingestion, page citations, FTS5 plus optional Qwen3 embeddings, structured Qwen3-8B answers, abstention, conversations, faculty corrections, evaluations and retention controls.
- Evidence-backed model laboratory with immutable ChEMBL snapshots, pChEMBL grey-zone and conflict removal, three-way scaffold splitting, a calibrated ECFP4 baseline, frozen evaluation metrics and applicability-domain warnings.
- Human-gated active-learning proposals using uncertainty, distance-to-training, QED and fingerprint diversity; no procurement or experiment starts automatically.
- Vina redocking benchmark using atom-order-preserving heavy-atom Kabsch RMSD; pose recovery never qualifies affinity scoring by itself.
- Result-linked interactive 3D compounds generated by Python/RDKit ETKDGv3, content-addressed by SHA-256, and rendered with zoom, rotation, representations, hydrogen visibility and selectable element/carbon colours.
- Data connector control center for NCI-60, TDC, COCONUT, NPASS, ANPDB, LOTUS, Tox21, EPA ToxCast, UniProt and Chemspace, with operator gates, checksums, immutable raw files and quarantine.

## Run locally

For a complete developer setup, environment reference and Docker workflow, read [`docs/DEVELOPER_HANDOFF.md`](docs/DEVELOPER_HANDOFF.md). The shortest path is:

```bash
npm run setup:local
npm run run:local
```

### Python API

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
PYTHONPATH=backend uvicorn app.main:app --reload --port 8000
```

### Next.js frontend

```bash
npm ci
NEXT_PUBLIC_OSIEL_API_URL=http://localhost:8000 npm run dev
```

When `NEXT_PUBLIC_OSIEL_API_URL` is absent, the frontend intentionally uses a clearly labelled embedded deterministic demo so the hosted preview remains executable.

### Public-source Open Discovery

Select **Open discovery** in the sidebar to run the inspectable disease/target/seed workflow. By default it performs real local Python/RDKit computation against the versioned reference registry and does not make outbound requests. To opt in to official public APIs, configure a contact-bearing user agent and enable the server gate described in [`docs/OPEN_DISCOVERY_WORKFLOW.md`](docs/OPEN_DISCOVERY_WORKFLOW.md).

The candidate priority score is a molecular-similarity and medicinal-chemistry heuristic—not target binding, efficacy, safety or probability of clinical success. The separate ZINC-22 panel can query a remote multi-billion SmallWorld map and locally assess a bounded returned shortlist. The Vina panel emits a score only when the connected, operator-enabled Python worker completes with prepared PDBQT inputs and a reviewed box. See [`docs/ZINC22_BILLION_SCALE_SEARCH.md`](docs/ZINC22_BILLION_SCALE_SEARCH.md) and [`docs/VINA_DOCKING.md`](docs/VINA_DOCKING.md).

### Optional local scientific copilot

Professor AI can call local Ollama/Qwen3-8B when explicitly enabled. The model receives only retrieved evidence and must cite supplied evidence IDs; invalid, unsupported or unavailable synthesis abstains. Approved PDF/TXT/Markdown sources, hybrid retrieval, conversations, faculty correction and evaluations are documented in [`docs/AI_PROFESSOR_ENGINE.md`](docs/AI_PROFESSOR_ENGINE.md).

### Post-experiment 3D compounds

Open **Experiments → 3D structure** after a run. Select a tested compound, drag to rotate, wheel/pinch or use buttons to zoom, change representation and apply element, cyan-carbon, purple-carbon or orange-carbon colours. A connected API generates and immutably stores the conformer with RDKit; the hosted demo uses the checked-in bundle generated by the same service. See [`docs/INTERACTIVE_3D_COMPOUNDS.md`](docs/INTERACTIVE_3D_COMPOUNDS.md).

### Evidence-backed model laboratory

Select **Model laboratory** to create an immutable, endpoint-specific ChEMBL snapshot, train a scaffold-separated baseline and inspect its frozen evaluation. The feature is operator-gated and never fabricates metrics when the Python API is absent. Configuration, APIs and scientific limitations are in [`docs/MODEL_LAB_AND_ACTIVE_LEARNING.md`](docs/MODEL_LAB_AND_ACTIVE_LEARNING.md).

## Verify

```bash
PYTHONPATH=backend pytest backend/tests -q
PYTHONPATH=backend python backend/scripts/e2e_demo.py
PYTHONPATH=backend python backend/scripts/e2e_open_discovery.py
PYTHONPATH=backend python backend/scripts/e2e_model_lab.py
PYTHONPATH=backend python backend/scripts/e2e_professor.py
PYTHONPATH=backend python backend/scripts/e2e_conformer.py
npm test
npm run build
```

Optional network/compute smoke tests are deliberately outside the deterministic verification suite:

```bash
PYTHONPATH=backend .venv/bin/python backend/scripts/e2e_zinc22.py
PYTHONPATH=backend .venv/bin/python backend/scripts/fetch_vina_example.py
PYTHONPATH=backend .venv/bin/python backend/scripts/e2e_vina.py
PYTHONPATH=backend .venv/bin/python backend/scripts/e2e_model_lab.py --live --max-records 1000
```

The E2E scenario ranks six candidates, selects three, creates an eight-dose/three-replicate protocol, produces 72 synthetic observations, passes reference QC, verifies that training eligibility is rejected, and confirms that the champion is unchanged.

The suite currently contains 52 passing backend tests. The literature API is available at `GET /v1/literature` and accepts optional `query` and `evidence_level` filters. Full-text articles are not copied; every record links to its authoritative PubMed entry.

`GET /v1/system/readiness` reports production blockers without hiding them. `POST /v1/plate-reader/imports/validate` retains the uploaded bytes unchanged by SHA-256, validates the reference schema, detects malformed or duplicate wells, reconciles controls and leaves every import quarantined until the university qualifies a model-specific adapter and a reviewer releases it.

## Production boundary

The reference is a contract-complete architecture demonstrator, not a production oncology model. The application now enforces explicit software gates for data provenance, raw-file retention, roles, review, audit and model promotion. It cannot manufacture the institutional evidence needed to clear those gates. Productionisation still requires an approved task dataset, a locked external evaluation set, prospective laboratory evidence, a named and qualified plate reader, PostgreSQL with the RDKit cartridge, managed object storage and workers, university OIDC, observability and tested restoration, POPIA/security review, SOP approval, and faculty sign-off. See the SRS for the explicit implemented, partial, adapter-ready, and contract-only disposition.
